# 官网创作资源地图

> 研究基准：2026-10-09。用途是帮助导演发现经营场景、玩法关系与选题线索；**不是产品功能真值表，也不是可直接改写后发布的文案库**。本地图记录可复用的研究方法与策略方向，不把官网页面上的参数、版本、效果数字或宣传措辞转成对外承诺。

## 一、证据层级与使用边界

1. **产品能不能说、具体规则怎么说**：先查本仓库 `spec/功能真值.json` 与 `spec/红线词表.json`。真值表未覆盖时，按 `AGENTS.md` 的要求回 `../applet` 源码取证；仍未覆盖就标为待确认，不根据官网页面、截图观感或行业常识补结论。
2. **官网负责发现问题与启发组合**：它可以提示“商家在什么时刻遇到问题”“有哪些常见策略路线”“某功能可能在一条经营链中承担什么作用”；它不替代产品实现证据。
3. **遇到页面间口径、版本或能力范围不一致**：不选一句看起来更好宣传的内容来用。记录冲突，回真值表和源码核验。对外视频仍遵守本项目不谈版本、档位、价格、升级等既定边界。
4. **不照抄**：不要复刻网页标题、段落、案例步骤、画面构图或营销钩子。把读到的内容抽象为“经营时刻—商家目标—顾客下一步行为—机制组合—成立条件”，再换成原创人物、行业细节、情境冲突和叙事顺序。
5. **一条片一个核心经营问题，不等于只讲一个功能**。功能数量由这条经营问题实际需要的因果链决定：一项足够就不硬堆；多项缺一不可，就把它们串起来讲清楚。不得拼盘式罗列卖点。

## 二、官网资源入口：分别拿来做什么

| 资源入口 | 主要用途 | 研究时重点看什么 | 不要直接搬用什么 |
|---|---|---|---|
| [首页](https://www.quandaokabao.com/) | 校准产品整体工作链和主要对象 | 商家操作、顾客领取、到店使用、后续经营之间的关系 | 品牌口号、转化话术、未经本仓库核验的概括性承诺 |

| [营销玩法](https://www.quandaokabao.com/marketing/) | 发现“经营问题如何组织成活动”的策略样本 | 活动触发点、目标顾客、希望对方下一步做什么、活动为什么有机会成立 | 原标题、完整步骤、案例句式，以及“用了就能带来某结果”的暗示 |

| [教程文章归档](https://www.quandaokabao.com/articles?type=tutorial) | 深挖细节、例外条件和容易讲错的操作逻辑 | 功能之间的先后顺序、支持与不支持的操作、用户最容易误解的概念 | 不核验就复述操作承诺，或把技术说明全部塞进视频 |
| [常见问题](https://www.quandaokabao.com/faq/) | 查边界、误区、术语差别和用户疑问 | 哪些看似相同的概念实际不同；使用前需要知道什么 | 把答案摘抄成客服式问答，或忽略当前真值表的口径 |
| [企业客户触达相关页面](https://www.quandaokabao.com/wecom/) | 理解顾客关系建立之后，首次触达与持续经营的策略位置 | 加好友、入群等行为分别处在顾客旅程的哪一阶段；发券只是第一步还是后续机制的一环 | 对外使用被本项目禁止的产品称谓；照搬站内引流和转化指令 |

单条视频不需要机械地把所有入口浏览一遍。先从经营问题出发，再选最相关的玩法页、行业页、功能详情和操作教程交叉阅读；遇到规则或概念疑问，再查 FAQ。研究引用应记录到本条导演稿，方便回查。

## 三、先把概念关系想清楚，再决定讲什么

下面是给导演使用的**概念地图**，具体定义、命名与限制一律以功能真值表为准。

- **优惠券**：针对某个消费或经营时刻设计的利益工具。不同券型解决的问题不同，选型应来自目标行为，而不是只因为某种券听起来更吸引人。
- **券包**：把多张或多种券组织成一个组合方案，适合表达“一个活动里有不同阶段或不同选择”。它不是单张优惠券的别名，也不等于“群发”。尤其要先核实本项目当前的发放方式限制，不能照搬官网把券包用于公开拉新的表达。
- **卡类产品（通卡、次卡、权益卡）**：用于表达持续使用、按次数使用或分项权益使用等不同关系，不应和一次性的优惠券混为一谈。是否真的适合某个行业，取决于服务频率、履约方式及真值表中的具体定义。
- **积分与会员权益/等级标签**：这是另一条客户关系管理逻辑，不等同于券余额，也不自动等于会员价、自动升级或积分兑换商品。未经真值表证实，不得把这些能力写成一个完整的自动会员系统。
- **“我的卡包”与“微信卡包”**：名称相近但不是同一个概念。提到顾客领取后的存放位置时，必须确认谈的是哪一个。
- **发放、领取、核销、转赠与奖励**：它们是经营链中的不同动作与状态，不要在文案中互相代替。尤其要区分奖励给实际核销者的机制，与受赠人完成核销后奖励原转赠者的机制；具体称呼按真值表。
- **公开领取与私密发放**：两种方式服务的目标和人群关系不同，并非任何卡券都可以任意切换。先确认要找新顾客、面向所有人，还是触达已知目标人群，再选择方式并核对能力边界。

这张概念地图不是让每条视频都解释一遍全部名词。只在某个概念差异会影响商家的判断、操作或最终结论时，才在口播中解释它；其余概念留在导演研究笔记即可。

## 四、用“经营链”寻找功能组合

研究任何玩法时，按这条链提问：

**经营时刻 → 希望改变的顾客行为 → 活动利益或产品载体 → 目标人群与触达方式 → 顾客领取/使用路径 → 下一次经营动作 → 如何观察结果。**

并非每条视频都需要覆盖链上的所有环节。只讲一个环节也可以；如果问题只有把多个环节串起来才能解决，就不要为了“聚焦单一功能”而把链条剪断。

| 经营问题方向 | 可以研究的组合思路 | 必须判断的关键条件 |
|---|---|---|
| 顾客买完就离开，之后没有再来的理由 | 把“本次消费结束”连接到“下一次到店理由”；再考虑优惠券规则、发放对象、适用时段、核销后的后续动作 | 券是否真的面向下一次消费；规则是否容易理解；提醒或自动触达能力是否已由真值表/源码确认；不能承诺必然复购 |
| 第一次体验后，没有形成稳定关系 | 根据服务是否适合重复使用，研究体验券、组合方案、按次数使用的卡类或分项权益之间的衔接 | 不要默认券包公开可领；判断用户是否已进入可以私密发放的触达路径；卡类要符合真实履约方式 |
| 老顾客沉默，需要一个回来理由 | 先明确什么样的顾客算“沉默”，再选择合适的专属利益、时间条件与触达动作，最后考虑如何观察使用情况 | 不要把“发出”说成“唤醒成功”；到期提醒、分群自动化等具体能力须逐项核验 |
| 老顾客带来新顾客 | 设计“老顾客愿意转赠—朋友愿意领取—朋友到店使用—谁在何时获得奖励”的闭环 | 奖励对象和触发条件要讲准；受赠者核销后奖励原转赠者，与奖励当前核销者不是同一回事 |
| 某些时段客流弱，商家又不想全店降价 | 围绕闲时、天气或季节来设计时间边界和使用场景，而不是把促销撒向全天、全店、所有顾客 | 时段设置、发放方式、适用门店等细节需证实；只能把“补一个到店理由”当策略目标，不能宣称结果必然发生 |
| 附近不同业态想互相带客 | 从双方顾客的实际需求和互补关系出发，设计体验、兑换或转赠等候选机制 | 不要暗示平台自带合作方市场、自动结算或自动导客；涉及跨店使用、统计归属等能力须取证 |
| 顾客价值、积分、会员身份和优惠券常被混着讲 | 先明确本条讨论的是累计/调整积分、人工分组、消费优惠，还是按次数/权益使用；再判断它们是否真有必要串联 | 不要凭“会员体系”的常识补出自动升级、等级折扣、积分换商品等未经确认的能力 |
| 活动发出后，商家不知道有没有人用 | 沿着发放、领取、核销和统计去找断点，解释数据能帮助回答什么问题 | 按真实统计指标描述；不能凭空补出趋势图、转化率、归因模型或经营提升幅度 |

以上只是**研究方向，不是现成脚本或功能承诺**。任何组合在写进导演稿之前，都必须先确认每个环节由什么动作或能力承担；缺乏证据的环节应删除、改成一般经营建议，或标为待确认。

## 五、行业页面应该挖出“时刻”，不是只换行业名

行业方案提供的是经营情境入口。创作时应该继续追问“这家店具体在什么时候遇到问题”，而不是写成“餐饮用优惠券、美业用次卡”这种空泛配对。

- **交易结束型**：吃完离店、买完商品、完成一次服务。思考这次结束之后，什么理由能自然连接下一次到店。
- **体验转长期型**：试听、体验课、首次洗护、首次健身或首次到店服务结束。思考顾客为何会停在第一次，下一步是否需要新的体验、重复使用或转介绍机制。
- **服务周期型**：洗车、美业、宠物护理、保养等有使用频率或周期的服务。思考顾客下次何时可能需要服务，不要把不确定周期说成固定规律。
- **时段/季节型**：下午空档、雨天、节日前后、开学/出游前后。思考需求发生的具体时点和可承接的服务容量，不要靠大幅促销强行制造因果。
- **一次性决策后沉默型**：摄影、家装咨询、数码家电、活动娱乐等。思考交易或咨询之后还存在什么合理的后续服务、关联需求或转介绍机会。
- **家庭/多人关联型**：亲子、教育、餐饮、宠物等可能涉及家庭成员或朋友共同参与的消费。思考转赠、同行体验或再次使用是否自然，而不是为了使用某功能硬加“老带新”。

这些分类可横跨行业。真正的创意来自具体人物、时间、空间、道具和经营矛盾；相同行业的不同门店也不应该默认使用同一种方案。

## 六、每条视频的官网研究记录

开始写口播前，在导演稿的前置摘要或研究笔记中留下以下信息：

- **经营问题与场景**：问题发生在哪里、在顾客旅程的哪一个时刻；哪些是已知现象，哪些只是待检验原因。
- **官网参考入口**：本次实际读过的功能页、玩法页、行业页、教程或 FAQ 链接；写明它分别提供了什么启发，而不复制原文。
- **候选组合与分工**：列出候选能力/经营动作，各自负责链条中的哪一步，前后如何衔接；允许只有一个，也允许有多个。
- **采用/舍弃理由**：为何这组机制比其他候选更适合当前问题；某项功能是否只是“看起来很丰富”但对解决问题没有必要。
- **成立条件与边界**：顾客是否能触达、何时领取和使用、是否受券型或发放方式限制；未证实的能力单独列明。
- **事实依据**：产品能力指向功能真值表与必要的源码证据；官网页面只记录为场景/策略灵感来源。
- **原创转化方向**：本片要用什么独有的门店环境、人物关系、动作和叙事推进来解释这条逻辑；不能只把官网案例换店名。

研究完成后再写口播、设计分镜与画面。逻辑链是导演的思考工具，不意味着要在画面中画成流程图；优先让人物在真实经营场景中通过动作、选择、反应和结果变化承载叙事，辅助信息仅在有必要时出现。

## 七、持续维护方式

本地图只维护长期可复用的官网入口、问题分类和组合思考方法。每条视频的一次性案例、画面细节和具体核验记录留在该片目录，不回写成全局规则。官网页面更新时，可以据此发现新的题材，但不得自动覆盖 `spec/功能真值.json` 或既定红线。
